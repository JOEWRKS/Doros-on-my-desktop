# 1분 간격 DORO? / 3분 수면 — 현재 구현 범위

## 사용자 요청

“기본3분”, “1분30초 동안 동작이 없으면 잠드는 대신 돌아다니다가 고개를
갸웃하며 말풍선으로 DORO?”가 최초 요청이었다. 이후 앞쪽 기울기를 수락하고
첫 반응을1분으로 단축,1분마다 반복, 자동 눕기ON은3분에 수면으로 전환하도록
명시 요청했다. 아래 조건은 이 후속 요청을 반영한다.

## 기존 제품과 연결

- 시간 기준은 기존 도로롱 미상호작용 타이머다. OS 전체 키보드/마우스 유휴
  시간을 새로 수집하지 않는다. 자율 보행은 미상호작용에 포함한다.
- 60초가 되면 기존 보행 속도/모션/3~7초 보행 구간을 사용한다. 그 뒤 멈춰
  3초 동안 머리만 최대8도 기울였다 복귀하고 `DORO?`를 표시한다.
  후속 사용자 요청에 따라 기울기는 몸쪽이 아닌 얼굴 앞쪽(몸 반대쪽)이다.
- 반응 시작을 기준으로60초 간격으로 반복한다(60/120/180/...초). 보행과
  질문 시간이 간격에 덧붙지 않는다. 질문은 수면 시계를 초기화하지 않는다.
- 자동 눕기ON이면60/120초에 반응하고180초에는 질문보다 수면을 우선한다.
  자율 보행 중이어도180초에 수면으로 전환하며 진행 중 질문 플래그는 지운다.
- 클릭·드래그·볼/발 조작·추적/간식 놀이·앉기·크기 조절은 질문을 취소하고
  미상호작용 기준을 초기화한다. 다른 직접 조작과 말풍선/고개 기울기를 겹치지 않는다.
- 기존 자동 눕기OFF는 저장값을 유지한다. OFF면 수면 없이60초마다 계속
  반응한다. 타이머/단계 진행은 기존 공중·매달리기·플랫폼 조회 불가·수동 앉기
  중 자율 동작 정지 정책을 따른다. 장시간 프레임 공백을 정상180초 실행으로
  간주하지 않는다.
- 기존 원화·팔·화남/웃음·걷기 속도·낙하 판정은 변경하지 않는다. 말풍선은
  클릭을 가로채지 않는 재사용 벡터1개이며, 프레임별 이미지 캐시는 추가하지 않는다.

## 플랫폼 및 검증 경계

현재 Windows 제품에 새 질문 표시를 연결한다. Core 기본 수면은180초로
변경하며, 질문은 표시를 구현한 호스트만 명시적으로60초 기능을 켠다. Mac의
새 질문 말풍선 연결/테스트 앱 재배포와 native 검증은 이번에 완료했다고 하지 않는다.

Core 시간/취소 검사, 실제 Windows presenter의100/125/150%·양방향 전체3초
프레임, 끝점 복귀·발 위치·다른 동작 중 취소·말풍선 재사용을 검사한다.
합성 타이머 검사를 실제3분 사용 검수 또는 사용자 외형 수락으로 확대하지 않는다.

제품 정의 스킬의 발견/조건 분리 원칙을 참고했다. 기존 저장소에는 V2
canonical planning state가 없으며, 이번에 별도 기획 체계로 이관하거나
V2 Semantic Closure/정확한 Manifest 사용자 승인을 취득했다고 주장하지 않는다.
현재 요청과 기존 TASKS/ROADMAP의 좁은 구현 기록으로 범위를 보존한다.
