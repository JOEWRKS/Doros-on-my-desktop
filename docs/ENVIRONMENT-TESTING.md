# 다른 환경 검증 · Environment acceptance

배포 후보 파일 하나의 SHA256을 고정하고, 아래 표를 PC별로 기록합니다.
자동 테스트 통과는 다른 PC에서의 실제 설치·화면 검증을 대신하지 않습니다.
This is a test plan, not a claim that these environments have passed.

## 가상화 없이 진행하는 방법

1. 별도 Windows 11 x64 PC 1대 이상에서 일반 사용자 계정으로 테스트합니다.
   개발 도구나 .NET을 미리 설치하지 않아도 실행돼야 합니다.
2. 같은 PC의 새 사용자 계정은 사용자별 설치·권한 검증에 도움이 되지만,
   다른 하드웨어/OS 또는 깨끗한 PC 검증으로 기록하지 않습니다.
3. 모니터·배율 검증은 실제 다른 배율의 모니터 두 대에서 진행합니다.
   원격 데스크톱·가상 머신만으로 실제 작업표시줄/GPU 동작을 인증하지 않습니다.

Windows Sandbox는 선택 사항입니다. BIOS 가상화가 필요하므로 이를 쓰지 않는다면
별도 실제 PC를 사용하면 됩니다. 이번 작업은 BIOS·보안 설정을 바꾸지 않습니다.
[Microsoft Sandbox requirements](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-install)

## 최소 테스트 표

| 환경 | 확인 항목 | 상태 |
| --- | --- | --- |
| Windows 11 x64, 표준 사용자, SDK/.NET 별도 설치 없음 | 설치·시작 메뉴·실행·제거 | 미검증 |
| 100%, 125%, 150%, 200% 배율 | 크기·선명도·클릭/드래그 위치·트레이 메뉴 | 미검증 |
| 서로 다른 배율의 모니터 2대 | 좌우·상하 이동, 음수 좌표, 주 모니터 변경 | 미검증 |
| 모니터 분리/재연결·해상도 변경 | 화면 밖 유실 없이 표시·입력 복구 | 미검증 |
| 작업표시줄 자동 숨김·보조 모니터 | 매달리기 판정·앞뒤 순서·메뉴 | 미검증 |
| 절전·복귀·잠금·해제 | 정지/유실 없이 정상 복귀 | 미검증 |
| 이전 공개판 → 후보판 | 정상 종료 후 업데이트, 데이터·바로가기 유지 | 후보별 검증 필요 |
| 한글/공백 사용자 경로 | 설치·로그·실행·제거 경로 정상 | 미검증 |

지원 범위를 넓히려면 Windows 10/ARM64 등을 각각 별도로 검증해야 합니다.
현재 x64 후보의 성공을 다른 아키텍처 지원으로 해석하지 않습니다.
배율 이동·도킹·실행 중 배율 변경은 서로 다른 시나리오입니다.
[Microsoft high-DPI testing guidance](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-desktop-application-development-on-windows)

## PC당 실행 순서

1. Windows 버전/빌드, CPU 아키텍처, 모니터 해상도·배율, 후보 버전/SHA256 기록.
2. 기존 펫 종료 → 설치 → 시작 메뉴 실행. 관리자 권한 요구 여부 기록.
3. 중복 실행 시 한 마리만 유지되는지 확인.
4. 트레이 좌/우클릭, 바깥 클릭·Esc 닫기, 로그 열기, 정상 종료 확인.
5. 머리 이동·볼 복원·마우스 추적/도약·수면 깨우기·매달린 앞발 확인.
6. 창/작업표시줄 가장자리와 모니터 경계에서 드래그·놓기 반복.
7. 30분 사용, 절전 복귀 후 멈춤·과도한 CPU/메모리·화면 밖 유실 확인.
8. 별도 테스트 PC에서만 제거·재설치: 프로그램/바로가기 제거와 로그 보존 확인.

서명 경고와 실제 설치 실패를 구분하고, Defender/SmartScreen을 끄지 않습니다.
문제 보고에는 재현 단계와 필요한 화면만 첨부하며, 계정명·개인 창·로그의 개인
경로는 공유 전에 가립니다. 앱은 결과를 자동 전송하지 않습니다.

## 기록 양식

후보 버전 / SHA256:
OS 빌드 / 아키텍처 / 배율 / 모니터 배치:
검사항목 / PASS 또는 FAIL / 재현 단계 / 화면·검토한 로그:
검사자 / 날짜:

현재 보고서는 미검증 항목을 열어 둡니다. 실제 결과를 받기 전 PASS로 바꾸지 않습니다.
