# r57 팔 경계·볼 반동·몸 선 — 수정 후보, 실제 조작 미검증

## 사용자 실패 보고와 범위

r56 `feedback-release-app`은 사용자가 겨드랑이/팔 끝 잔선, 당긴 볼 선 뭉개짐,
놓은 볼의 중복 선, 두꺼워진 몸 선을 지적했다. 따라서 이 후보는 불합격이다.
추가 선택으로 **캐릭터를 확대해도 몸 선은 1배 두께에 가깝게 유지**를 승인했다.
얼굴/머리의 선 두께와 원화 파일은 변경 대상이 아니다. 설치·Mac·배포·Git 원격은
이번 작업에서 변경하지 않는다.

## 확인한 원인과 변경

- 볼 반동: 고해상도 음수 pull의 역좌표가 선택된 피부 바깥으로 나갔다. 원래
  `CheekPullRenderer`는 Skin..Root로 clamp하지만 이식 경로에는 clamp가 없어
  볼/머리의 바깥 ink를 피부 안쪽에 다시 샘플했다. 같은 clamp를 복원했다.
  초기에 "바깥 윤곽도 이동해야 한다"고 추정한 것은 틀렸다. 바깥을 옮긴
  cheek-v1은 머리와 볼 사이 흰 틈을 만들었고 직접 열람 후 폐기했다.
- 당긴 볼: target 곡선 기울기만 보정하던 collar 대신 source/target 법선의
  비율을 함께 사용한다. 눈·머리 파츠를 덧붙이거나 선을 다시 그리지 않는다.
- 팔: 사각형에 가까운 기존 잘라내기 마스크에는 몸 ink와 흰 외부 여백이 같이
  들어 있었다. 회전 때 그 경계가 따라 나왔다. r33에 기록된 원래 앞발 Bézier와
  등록 좌표를 사용해 분리된 runtime 파츠를 만들고, 팔 아래 몸판은 기존 y85
  단면으로 연결했다. 최대 어두운 픽셀 탐색에 의존한 `TrimOuterFringe`는 제거했다.
  4Hz 엇갈림과 각도는 그대로다. 원화 PNG/은행을 수정한 것이 아니다.
- 몸 선: 같은 크기의 등 한 구간은 이전 약1.295 logical px, 수정 전 현재
  1배 약1.321 logical px였다. 과거 이중 덧칠 문제의 재발이라고 확정하지 않는다.
  1.5배 출력에서 약2.011 physical px로 늘어나는 것은 확인했다. 승인에 따라
  몸 레이어만 선 양쪽 coverage를 줄이는 표시 보정을 추가했다. 내부 흰 면,
  기존 ink 색, 보간 sampler는 유지한다. 원본 배열은 수정하지 않으며 캐시한다.
  1배는 입력 배열을 그대로 돌려준다. 원본 재사용 버퍼의 캐시도 무효화한다.
  Windows DPI 배율과 사용자 크기를 분리하여 DPI 자체 때문에 얇아지지 않게 했다.

### 후속 실행 — 사용자 종료 확인 후

사용자가 종료했다고 응답한 뒤 `Dororong.App.exe`/`Dororong.exe` 프로세스가 없는
것을 확인했다. 위 r57 Release를 `--high-resolution-grab=1.5`와 로컬
`--performance-capture=.../contour-feedback-20261018-r57/native-20261018.json`으로
실행했다(PID122860). 기록은60초 WPF callback/입력/발판 진단이며 화면 FPS가 아니다.
이 실행은 설치본 교체가 아니다. 프로세스 실행 사실과 실제 조작의 시각 검증을
구분하며, 사용자 볼·바동거림·붙기 확인은 아직 대기 중이다.

## 남은 문제 / 다음

실제 Release의 볼·팔·작업표시줄 동작, flutter에서 붙기로 바뀌는 순간,
큰 크기의 tick 지연과 r56에서 남긴 전체 모션 정합은 미완이다. 저장 표본 개선과
자동 통과를 실제 조작/전체 완료/사용자 수락으로 바꾸어 보고하지 않는다.
새 Release는 위 후속 실행으로 켰다. 실제 동작 확인과 설치·출시는 계속 보류한다.
