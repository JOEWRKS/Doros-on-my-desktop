# r60 추적 눈 영역 분리 — 저장 검수, 실제 조작 확인 대기

**후속 사용자 반려:** 눈 내부가 찌그러지고 시선 이동이 부족하다는 실제 피드백이 왔다.
아래 검사/열람은 그 요구의 충족을 입증하지 못했다. 원인과 수정·미검증 범위는
[r61 기록](2026-10-18-r61-rigid-gaze.md)을 따른다. 이 후보를 수락본으로 취급하지 않는다.

## 승인 범위와 수정

사용자가 눈 이동 영역만 분리하고 수락한 머리·볼·몸을 유지하도록 지시했다.
제품 수정은 `HighResolutionFacePose.cs`의 gaze 샘플 좌표 선택뿐이다.
원본 r33 머리를 좌표 격자로 확대해 두 눈 안쪽 경계를 직접 확인했다.
넓은 직사각형 Bump 대신 눈 내부 행별 경계와 고정 collar/연속 falloff를 사용한다.
머리 전체 기울임 행렬·추적 시간·볼 당김/반동 선택·몸 선·샘플러는 변경하지 않았다.
눈 자체의 테두리까지 옮기는 방식이 아니라 테두리는 두고 내부 시선만 이동한다.

`pixel-comparison.json`의 protectedChanged는 0이다. 설치본·설정·Mac·배포는 미변경.

## 기술 검사와 실패 기록

출력: `artifacts/gaze-isolation-20261018-r60/`.

- 수정 전 기준 생성: GazeFrames 5개 통과, before/385 PNG.
- 첫 신규 검사: 8 통과, 1 실패. 이동량 0.85 비교가 실제 이진 연산 결과
  0.85000000000000142로 실패했다. `r60-gaze.trx`에 실패를 보존했다.
- 수정은 테스트의 이동량 상한에 1e-12 수치 오차를 허용한 것뿐이다.
  영역 밖 좌표의 완전 동일 조건이나 제품 마스크는 느슨하게 하지 않았다.
- 후속 보존/몸 선/볼 루프 회귀 13개 통과 (`r60-regression.trx`).
- 최종 Release 고해상도 관련 전체65개 통과, 실패0/건너뜀0
  (`r60-all-related.trx`, 1분28초). 자동 통과를 실제 조작 통과로 해석하지 않는다.
- 5개 크기 × 8방향 × 9왕복 단계 = 360장의 변경 픽셀은 독립적으로 정한 두 눈
  주변 사각 범위를 벗어나지 않았다 (`gaze-locality.json`, outside 합계 0).
  색상만으로 머리 여부를 판정하지 않았다. 진단 pink 조건 46건은 머리 보존의
  실패/통과 판정으로 쓰지 않는다. 표본 (39.545,59.545)는 오른쪽 눈 하단 갈색
  테두리의 1단계 색 변화이며, 실제 분류에는 원본 위치·윤곽을 대조했다.

## 직접 열람한 시각 증거

`source-grid.png`로 원본과 선택 경계를 확인했다. `eyes-1.00/1.10/1.25/1.35/1.50.png`
5시트에서 360개의 고정 머리각 시선 왕복 표본을 열람했다. 눈 옆 분홍 머리,
중앙 앞머리 끝, 볼 윤곽의 국소 이동은 이 표본에서 발견하지 않았다.
`loop-sheet-1.00/1.25/1.50-{0,1}.png` 6시트에서 합성 포인터를 실제 PetLoop/Presenter에
넣은 진입18+복귀30 프레임씩, 총288장을 직접 열람했다. 머리 전체 각도는 기존
모션대로 변하며 눈 옆 머리의 별도 밀림은 발견하지 않았다.
이 시트는 시각 확인용 crop/확대이며 실제시간 연속 재생·데스크톱 마우스 조작
또는 전체 동작/성능 검증 통과가 아니다. `comparison.png`는 중립/이전/수정의
같은 크기·같은 머리각 오른쪽 추적 대조다. 모든 아트가 무결하다는 의미는 아니다.

## 실제 실행과 미검증

이전 r57 불투명 진단 창은 Alt+F4 시도로 종료가 확인되지 않았다. 사용자에게
트레이 종료를 요청했고 확인 후 프로세스와 대상 창이 없음을 확인했다.
r60 Release win-x64 self-contained publish 성공 후 정상 투명 모드1.5배로 실행했다
(PID26260, `release-app/Dororong.App.exe`). 이전 진단 창 복원 미완은 이 정상 실행으로 대체한다.

computer-use의 list_windows에는 새 투명 창이 없고 list_apps에도 설치본 windows[]만
반환됐다. 관찰되지 않은 좌표를 추측해 조작하지 않았다. 사용자에게 실제 좌우/상하
추적·복귀 확인을 요청했으며 아직 응답이 없다. native.json은60초 실행 기록이지만
입력 marker가 없고 호버 완료 증거도 아니므로 실제 조작 통과로 처리하지 않는다.
이번 실행은 다른 검사와 겹쳤으므로 성능 개선의 비교 기준으로 쓰지 않는다.

다음은 사용자 실제 결과 확인과 필요 시 해당 경계만 보완이다. 전체 모션 정합,
버벅임·붙기 등 이전 미완, 여러 DPI/모니터의 실제 검증, 설치/배포는 닫지 않는다.
