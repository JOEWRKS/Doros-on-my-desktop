# r76 볼 입력 순서·렌더 할당/참조 수정 — 실제 재측정 대기

## 범위와 상태

사용자 요청 순서대로 엎드린 씰룩임 중 볼 잡기 자세 초기화부터 수정한 다음 렉/메모리 경로를 수정했다.
r70 수락 원화/몸/발/얼굴/머리 끝/선 및 간식 속도를 보존한다. r75의 화면 합성 주기 갱신도 유지했다. 프레임률 제한이나 화질 저하로 비용을 줄이지 않았다.
실행 프로세스 부재를 확인한 뒤 재측정 준비를 물었고 사용자가 **“ㄱㄷ”**이라고 답했다. 후보 실행·측정은 시작하지 않는다. 설치본/설정 변경 없음.

## 1. 볼 잡기 전에 자세가 원복되는 경로

- UpdateHuntingCore가 물리 버튼 눌림을 먼저 읽으면 routed MouseDown의 볼 타깃 분류/현재 자세 캡처 이전에 몸을 초기화했다.
- 고해상도 엎드림 준비 중 아직 타깃이 없는 눌림에는 마지막 표시 자세를 유지한다. 관련 준비/시선 시간도 진행시키지 않는다. 이벤트가 도착하면 기존 볼 캡처/렌더 경로로 넘긴다.
- 일반 버튼 유지로 수면/간식/매달림/점프를 붙잡지 않도록 범위를 제한했다. 이벤트 없이 놓으면 다음 tick에 정상 재개한다.
- `CrouchedCheekOrderingTests`: 5크기(1/1.1/1.25/1.35/1.5), 폴링0/1/3회 순서9조합에서 엎드린 BodyFrame 보존→볼 당김→놓기→상호작용 종료 확인. 별도 이벤트 없는 버튼 유지/해제 재개 검사도 추가했다.
- 이 검사는 실제 PetLoop/presenter에 입력을 주입한 검사다. 실제 OS 이벤트/화면 검수나 사용자 수락을 대신하지 않는다.

## 2. 반복 할당 및 비용

- 목 연결부: 렌더별 약1MB의 byte/float 배열을 재사용하고, 같은 BodyFrame/Head 행렬이면 기존 출력 재사용. 바뀐 원본/선 보정/윤곽 캐시를 명시적으로 무효화한다.
- 몸 선 보정: 원본 scratch의 무효화 시 파생 float 배열을 버리지 않고 지운 후 다시 채운다. 원래 연산/샘플링/선 굵기 유지.
- 엎드림 몸과 착지 퍼짐 소스: 기존4개 캐시 상한 유지, 퇴출 배열을 재사용. 동기 raster 호출이 끝나면 다시 쓸 수 있는 내부 임시 버퍼이며, 완성 Bitmap은 자체 복사본이다.
- 불변 소스 윤곽: 전체 알파 영역 반복 스캔을 약한 참조 키의 원본별 경계 캐시로 대체. 행렬/배율/여백 계산은 그대로. 재사용되는 배열은 관련 경계를 무효화한다. 캐시가 폐기된 원본을 살려두지 않는 검사 포함.
- 5크기×7종×12표본=420개 픽셀이 변경 전 baseline과 일치. 기존 r72 변경 전360개와도 차이0. 발 접촉 밴드와 Bitmap scratch 재사용 검증 포함. 새 시각 열람/OS 화면 검수를 했다는 뜻은 아니다.

## 3. 실제 회수 실패와 수정

- 새 WeakReference 검사가 렌더 객체 폐기 후 강제 GC에도 살아 있음을 재현했다(`allocation.trx`:1실패/3통과).
- 작업자 루프의 마지막 Action 지역변수에 null을 넣는 1차 시도도 실패했다(`lifetime-fixed.trx`:1실패/5통과). 이 시도를 성공으로 간주하지 않는다.
- 큐 항목이 렌더 delegate를 실행하기 전에 Interlocked.Exchange로 비우도록 바꿨다. 소비자가 마지막 큐 항목을 보유해도 렌더 원본/임시 데이터는 더 이상 연결되지 않는다. 같은 객체 회수 검사와 작업자 예외/병렬/정확히1회 처리 검사6개 통과(`lifetime-envelope.trx`).
- 이는 폐기한 객체의 잔류 참조 결함이다. 앱 전체의 시간에 비례하는 무제한 누수가 모두 제거됐다는 뜻은 아니다.
- 측정 완료 후 MainWindow가 보유하던 capture 객체의 frames/ticks/states/inputs 목록도 저장 성공/실패와 관계없이 비우고 용량을 반환한다. 출력 경로가 디렉터리여서 저장 실패하는 경우와 중복 Dispose에서도 해제되는 검사 통과.
- 실제 실행 옵션에1초 간격 managed heap/private bytes/working set/handle 기록 추가. 강제 GC는 테스트에서만 사용하고 제품 실행에서는 하지 않는다. 누적 할당량은 현재 보유량/누수량과 구분한다.
