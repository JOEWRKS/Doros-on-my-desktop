# r55 — 상태 연결 후보와 버벅임 확인 / 전체 미완

## 판정과 범위

사용자는 전체 연결·동작 검증을 요청한 뒤 프레임 드롭 같은 버벅임을 지적했다.
후속 지적부터 새 상태 확장보다 성능 원인 확인을 우선했다. **전체 완료·시각 통과·실제 입력 통과·60fps 보장은 아니다.**
설치본/기본 실행/Mac/배포/commit/push는 변경하지 않았다.

## 실제 변경

- `HighResolutionLocomotion`과 생성기를 DLM2 837항목으로 확장했다. 기존 감은 머리/걷기/앉기에 달리기384, 수면 몸65/앞발 효과65, 매달리기 몸1을 추가했다. 원화 PNG와 grab bank는 유지했다.
- `HighResolutionStates`, `HighResolutionPerch`, `HighResolutionSnackEffects`에 수면/깨우기, 몸 클릭 반응, 호기심/놀람, 간식/식후 반응, 매달리기/앞발 당김 후보를 연결했다. 몸 클릭은 이제 ClickOnly 대상이며 누른 순간의 자세를 유지한다. 씹기는 기존 입의 소스 좌표 변형이다. 이것은 기존 동작과 모든 타이밍이 일치한다는 검증 결과가 아니다.
- 볼 근처 눈의 선택 경계를 원본 좌표에 맞춰 확대했다. 초기 수면 효과가 입 근처에 표시되는 결함을 저장 시트에서 발견하고 효과 좌표를 머리 로컬로 고쳤다.
- 일반 자세에서 머리 잡기를 시작할 때 캡처 자세를 보존하고 진입 초반35%에 중립으로 복귀하도록 후보를 추가했다. 전체140ms는 유지하지만 내부 시간 배분·시각 연속성은 아직 미검증이다.
- 기본 창을 native UI 도구가 찾지 못해 `--interaction-test-window` 진단 플래그를 추가했다. 이 옵션에서만 작업표시줄 표시/활성 창 정책이 달라진다. 이 진단 창은 아직 실행하지 않았으며 기본 no-activate 동작의 검증을 대신할 수 없다.

## 버벅임 원인과 수정

검사본을 Debug로 실행한 것은 성능 확인에 부적절했다. 실제 해당 검사본의 1.5배 소스 샘플러는 평균 평상시27.95ms/추적27.74ms/볼41.22ms/잡기35.50ms/착지75.72ms였다. 수치는 그림 한 장의 CPU 생성 시간이며 실제 화면 FPS가 아니다.

Release에서도 무거운 CPU 소스 재샘플링이 남는다. 특히 `ApplyHighResolutionPlatform`은 발 위치/펼침/압축·기울임/소수 픽셀 보정을 위해 여러 차례 그림을 생성할 수 있다. 렌더는 UI 루프에서 동기 실행된다. 단순히 Debug를 Release로 바꾸는 것만으로 전체 문제가 해결되지 않는다.

적용한 최적화:

1. 실제 알파 영역에 맞춘 처리 범위, 효과 없는 좌표의 조기 반환, 동일한 보간 탭의 빠른 반환.
2. 색상 채널 벡터 연산과 bilinear 전용 경로. 보간 방법·샘플 수는 낮추지 않았다.
3. 볼 곡선의 기존24단계 이분법 결과를 보존하는 빠른 조회. 44,004개 좌표/강도 조합이 double까지 일치한다.
4. 압축 해제 중간 byte 배열 제거, 잡기 몸 캐시 재사용, 감은 머리 캐시 별도 유지. 동시에 빌려 쓰는 locomotion 파츠 배열은 재사용하지 않는다.
5. 머리 후행 움직임의 프레임 공통 pin 계산을 반복 픽셀 계산에서 분리했다.

착지 역변형의 Newton 근사 시도는 저장 착지 이미지가 달라져 **철회**했다. 최종 코드는 원래20회 이분법을 유지한다. 48,750개 조합 비교에서 오차1e-12 이내다.

## 검사와 실행 경계

- `r55-final-related.trx`: 상태3+얼굴5+locomotion3+성능/수치3 =14통과.
- `r55-perf-isolated.trx`: 성능/수치3통과. 성능 기록 테스트 자체는 시간 합격 기준을 강제하지 않는다.
- `r55-loop-final.trx`: 합성 입력 기반 실제 루프5통과. 위치/캡처/낙하·착지 상태 조건이지 속도나 시각 합격 조건이 아니다.
- 앞선 Debug 전체 앱 검사는 성능 진단을 위해 중단했다. 최종 Release 전체 앱 검사도 완료 출력을 받기 전에 이번 성능 진단을 마감하며 중단했다. 둘 다 전체 통과로 세지 않는다. 최종 변경에 대한 완료 결과는 위14개 관련 검사와5개 루프 검사 범위다.
- Debug `artifacts/runtime-completion-20261018-r55/app/Dororong.App.exe --high-resolution-grab=1.5`를 잠깐 실행했다. native 도구의 앱/창 목록 및 명시적 실행으로도 대상 창을 찾지 못했다. 실제 마우스 입력/스크린샷 검증은 하지 못했다. 해당 검사 프로세스 PID4000은 경로 확인 후 종료했고 검사본은 현재 실행 중이지 않다.
- 머리 원화 `12d403f3…84edf`, 몸 원화 `53474e7c…648a`, grab bank `f3281baf…a04` 해시가 r54 기록과 같다.
