## 후속 질문: 엎드린 씰룩임에서 볼을 누르면 평상시로 복귀

사용자 보고에 따라 제품 수정 없이 진단했다. `DororongPresenter.Hunting.cs`의 UpdateHuntingCore는 물리 버튼 눌림 `pressed`만으로 blocked=true를 만들고, `_huntRecoveryAge=2.6`, hunt 세션/시선/블렌드를 즉시 초기화한다. 한편 `CreateHighResolutionPress`는 WPF MouseDown이 전달될 때 현재 `_hrFace`를 캡처하고, 볼 렌더는 그 Face를 유지한다.

따라서 실제 버튼 상태 폴링이 routed MouseDown보다 한 tick 먼저 처리되면, 볼 캡처 전에 엎드린 BodyFrame이 -1(평상시)로 바뀐다. 반대로 볼 이벤트를 먼저 받아 캡처하면 엎드린 BodyFrame은 유지된다.

`tests/Dororong.App.Tests/Runtime/CrouchedCheekOrderingTests.cs`에서 동일 실제 PetLoop/presenter의 두 입력 순서를 주입해 비교했다. 1.5배,1.2초 엎드림 준비 후:

- 이벤트 먼저 전달: 볼 타깃/캡처와 기존 BodyFrame 유지 확인.
- 버튼 폴링 먼저 전달: 타깃 None 상태에서 BodyFrame=-1로 즉시 복귀 확인.

`artifacts/render-cost-20261019-r75/tests/cheek-order-diagnosis.trx`2개 통과는 **현재 결함 경로를 재현한 진단 검사**이지 원하는 동작의 통과가 아니다. 최초 테스트 빌드의 테스트 helper 네임스페이스 오류를 수정하고 재실행했다. 제품 코드/실행본은 바꾸지 않았다.

이는 코드 경로/주입 순서 재현이며, 사용자가 방금 본 클릭의 실제 OS 이벤트 순서를 기록해 확정한 것은 아니다. 정확한 네이티브 순서는 추가 계측이 필요하다. 개선 방향은 볼 타깃 분류/자세 캡처 전에 일반 버튼 폴링으로 몸을 초기화하지 않게 순서를 분리하는 것. 사용자 질문은 원인 조사이며 수정은 아직 미실행이다.
