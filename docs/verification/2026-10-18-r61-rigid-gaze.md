# r61 눈 모양 변형 반려 후 평행 이동으로 수정

## r60 실패와 검사 한계

사용자가 r60 실제 실행에서 왼쪽 눈 오른쪽 부분의 모양만 달라지고 시선이 제대로
이동하지 않는다고 두 캡처로 반려했다. r60은 내부 좌표에 위치별 falloff를 곱했다.
머리 침범은 줄였지만 눈 내부의 이동량을 다르게 만들어 눈을 변형했다.
이는 사용자 요구를 충족하지 못한 구현이다. 기존 65개 통과, 648장 열람과 머리
보존 관찰은 눈의 제대로 된 추적/형태 보존을 입증하지 못했다. r60은 수락본이 아니다.

## 수정 범위

- FacePose.Source에서 gaze 변형을 제거했다. 볼 당김/반동/머리 반응 좌표 코드는 유지.
- `HighResolutionGrabRaster.Gaze.cs`에서 원본 눈 색/선을 `(x-EyeX,y-EyeY)`로
  동일 평행 이동한다. 눈 안쪽마다 다른 이동률·확대·찌그러뜨림은 없다.
- 원본 얼굴의 안쪽 피부 donor와 눈 matte로 이전 위치의 눈 기여를 빼고 이동한
  눈 기여를 더한다. 원본 머리 가림 영역은 정지한다. source와 destination 모두
  같은 원본 가림 범위를 사용해 원래 머리 픽셀이 눈 파츠로 이동하지 않도록 했다.
- 원본 이미지/bank는 다시 그리거나 교체하지 않았다. 기존 bounded cubic/coverage
  방식, 머리 각도/추적 시간 및 최대 시선 이동량(.85/.65 DIP)은 유지한다.
- 시선 0/감은 눈에서는 새 합성을 우회한다. 새로운 아트 생성이 아니라 런타임 합성 수정이다.

## 검사와 보존

증거 폴더: `artifacts/gaze-rigid-20261018-r61/`.

- trial: 1.5배 77개 정지/왕복/보존 PNG. 첫 샘플에 source 가림도 적용하는 보완 후
  final/에 새 출력을 만들었다. trial을 최종 결과로 쓰지 않는다.
- 최초 확대 검사 12개 중11 통과/1 실패 (`r61-gaze.trx`). 보호 픽셀 중심 x30을
  영역 밖이라고 판단했지만1.25배 해당 픽셀은 x29.8도 샘플링해 눈과 겹쳤다.
  검사에서 픽셀 전체 footprint가 보호 범위 안인 경우를 고르도록 수정했다.
  제품을 검사에 맞춰 더 변형하지 않았고 실패 로그도 유지한다.
- 새 검사: 실제 원본 머리 전체를 동일 평행 이동한 참조 렌더와 두 눈 내부의
  독립된 feature 창을 비교한다. 1/1.25/1.5배, 좌우/상하에서 채널 오차1 이내다.
  머리/입/볼/몸의 독립 보호 위치는 픽셀 동일. 가려진 경계까지 완전히 같은 모양이라고
  확대 해석하지 않는다. 실제 머리카락에 가려지는 부분은 고정된 가림을 따른다.
- 최종 Release 관련68개 통과, 실패0/건너뜀0 (`r61-related.trx`, 1분21초).
- 5크기 중립·볼 당김/반동 25개 PNG는 r60 이전 기준과 파일 SHA256 동일
  (`final/protection.json`).
- r58 shape-lock 대비 r33 머리/몸 PNG, grab/hunt-body/locomotion bank,
  BodyInk 및 Flutter 코드는 SHA256 동일. 설치·Mac·원격·배포는 변경하지 않았다.

## 직접 열람한 범위

final/eyes-1.00,1.10,1.25,1.35,1.50.png의 360개 방향별 왕복 표본과,
final/loop-sheet-{1.00,1.25,1.50}-{0,1}.png의288개 합성 입력 진입/복귀 표본을
직접 열람했다. 극단8방향 확대도 확인했다. 이전과 달리 홍채와 눈 하단 윤곽이 함께
좌우/상하로 이동하고 앞머리/옆머리는 제자리에 남는 것을 이 표본에서 관찰했다.
전체 런타임 모션 시각 통과·실제시간 연속 조작 통과는 아니다.
`final/left-neutral-right.png`는 같은 머리각·배율의 좌/중립/우 대조다.

## 실제 실행 경계

win-x64 self-contained Release publish 성공: `release-app/Dororong.App.exe`.
현재 PID26260은 이전 r60 실행본이다. 교체를 위해 사용자에게 트레이 종료를 요청했다.
아직 종료 응답이 없어 r61을 중복 실행하거나 기존 프로세스를 강제 종료하지 않았다.
따라서 r61 실제 실행·사용자 조작 결과는 미검증이며 실제 완료로 기록하지 않는다.
다음은 종료 확인 후 정상 투명1.5배 실행과 시선/복귀 실제 확인이다.
전체 모션 정합·버벅임·동적 발판 등 기존 미완은 그대로 남는다.

### 후속 실행 교체 · 2026-10-18

사용자가 트레이 종료 완료를 알렸고 Dororong.App.exe 프로세스가 없음을 확인했다.
준비된 r61을 `--high-resolution-grab=1.5`로 실행했다(PID110044). 재조회에서 r61
경로의 단일 프로세스, 해당 인수와 Responding=True를 확인했다. 불투명 진단 옵션은
사용하지 않았다. `native-after-replacement.json` 성능 수집을 요청했지만 이 실행
확인만으로 시각·실제 추적/복귀·성능 통과를 선언하지 않는다.
위 교체 대기는 해소됐고 다음은 사용자 실제 시선 이동/복귀 결과 확인이다.
설치본·설정 파일·원화·제품 코드는 이번 실행 교체에서 변경하지 않았다.
