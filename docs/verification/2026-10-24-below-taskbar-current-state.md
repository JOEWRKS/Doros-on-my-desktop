# 작업표시줄 아래 현재 위치 원인 — 2026-10-24

## 결론

현재 보조 모니터 작업관리자 창의 경계가 작업표시줄 윗변을5px 덮고 있다.
현재 발판 알고리즘은 이 창의 전체 가로 범위에서 작업표시줄 발판을 제거한다.
이 실측 장면을 현재 배포 DLL의 물리에 넣으면40px 아래 화면 바닥으로 떨어진다.
작업관리자 창 하나만 진단 장면에서 제외한 대조군은0px 이동한다.
실제 실행 중인 도로롱의 창 좌표도 화면 바닥 위치와 일치한다.

이는 현재 낮은 위치를 설명하는 직접적인 경계/코드/재생 근거다. 최초 낙하
순간의 내부 이력은 없으므로 그때 작업관리자가 이동했는지, 도로롱이 이 구간으로
걸어왔는지, 캡처 동작이 있었는지까지 확정하지 않는다. 이전 투명 NVIDIA 창이나
메타데이터 만료 수정의 재발이라고 단정할 근거는 없다.

## 코드 경로

`PlatformGeometry.Build`는 앞쪽 창이 발판의 윗변을 세로로 조금이라도 덮으면
그 창의 가로 폭을 remaining에서 뺀다. Taskbar 예외는 transient menu뿐이다.
가려진 깊이가5px든40px든 결과는 해당 폭의 taskbar surface 제거로 같다.
`PlatformMotion.Advance`는 같은 키의 지지 면에 발 겹침이 없어지면 Falling으로
전환하고 다음 교차면인 monitor floor에 착지한다. 새 그루밍 그림/모션 없이도
이 현상이 재현된다. 전체 HWND 아래쪽1226은 투명 여백 포함값으로, 캐릭터가
화면 밖146px 잘렸다는 뜻이 아니다.

## 범위와 미확인

이번 요청은 현재 원인 확인이다. 제품 동작, 설정, 설치본, 실행 앱은 변경하지
않았다. 강제GC/trim/덤프/일시정지/주입/자동 입력/재시작 없음.
일반 창의 얕은 겹침에서도 작업표시줄 위를 유지할지 여부는 발판 정책 변경이며,
수정한다면 전체화면/진짜 숨김/일반 창 발판 소실과 구분해야 한다. 이번 턴에
모든 taskbar occlusion을 무시하는 임의 변경을 하지 않았다.
