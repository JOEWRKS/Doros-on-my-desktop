## 후속 사용자 보고

새 실행을 반복시키기 전에 이번 터미널의 출력 파일 경로/완료 상태를 확인해야 한다.

도로롱 담당은 앱 문제를 해결하도록 요청했다. 보고서는 지정 채팅

맥 상단 제한/낙하 초반 위치 불일치의 수정 후보와 진단 실행기 보강을 구현했다.
**실제 Mac의 문제 해결·ARM64 콜백 실행·Gatekeeper 실행은 NOT_TESTED다.**
호스트 자동 검사를 네이티브 해결로 바꾸어 보고하지 않는다. 별도 렌더 지연은
확정되지 않았으며, 같은 위치 로그를 사용자에게 다시 요청하지 않았다.

## 변경

### 1. 펫·간식 창만 화면 상단 프레임 제약 해제

`OverlayFramePolicy`는 현재 Avalonia `AvnWindow`/`AvnPanel`의 하위 클래스를 등록하고
명시적으로 전달된 소유 오버레이 인스턴스에만 적용한다. 전역 클래스의 메서드를
교체하지 않는다. 메뉴·다른 창은 변경하지 않고 기존 이벤트/레이아웃/수명 처리를 상속한다.

`constrainFrameRect:toScreen:` 콜백은 제안된 프레임을 그대로 반환한다. 이것은
투명 여백까지 화면 안에 붙잡아 놓는 정책을 해제하기 위한 것이며, 캐릭터의 가시
범위 제한은 기존 컨트롤러가 계속 담당한다. 이동 좌표·렌더 원점·히트테스트·낙하 속도·
물리 곡선은 변경하지 않았다. API 교체만으로 해결됐다고 추측하기보다 목적에 맞는
제약 정책을 별도 구현했다.

Apple은 이 메서드를 하위 클래스에서 재정의하여 화면 제약을 없애거나 변경할 수 있다고
설명한다. [Apple 공식 문서](https://developer.apple.com/documentation/appkit/nswindow/constrainframerect(_:to:)?changes=l_2).
다만 문서의 자동 호출 설명은 제목 있는 창을 언급하므로, tester의 borderless 창에서
관찰된 제한이 이 메서드 경로를 거치는지는 실제 native 실행으로 확인해야 한다.
기존 [Avalonia11.3.22 AvnWindow 소스](https://raw.githubusercontent.com/AvaloniaUI/Avalonia/11.3.22/native/Avalonia.Native/src/OSX/AvnWindow.mm)에는 해당 재정의가 없다.

- 네이티브 메서드의 원래 type encoding을 재사용하며 CGRect는4개의double(32bytes).
- Apple Silicon에만 설치한다. Intel ABI를 검증 없이 지원한다고 하지 않는다.
- 콜백은 정적으로 유지하여 GC로 사라지지 않게 한다. 소유 창/프레임 버퍼를 캡처하지 않는다.
- 클래스 캐시는 최대2개이며 같은 창을 다시 구성해도 클래스/콜백이 누적되지 않는다.
- 모르는 창 클래스/등록 실패는 명시 오류로 중단하며 임의로 다른 창을 바꾸지 않는다.
- 진단에 callback 호출 누적 횟수를 추가해 실제 호출 여부를 확인할 수 있게 했다.

### 2. 진단 실행기: 파일 위치와 실행 상태를 실제로 확인

- 같은 폴더의 test08 앱 우선, 없으면 `/Applications`·사용자 Applications의 test08을 확인.
  맞는 버전이 없거나 위치가 모호하면 실행 전 실패를 알린다. 무관한 앱을 실행하지 않는다.
- 커맨드가 앱을 직접 켠다고 사전 표시한다. 앱 실행 요청과 기록 시작을 구분한다.
- 매 실행의 GUID를 앱에 전달하고 그 세션의 새 로그만 기다린다. 이전 파일을 성공으로
  오인하지 않는다. 세션 인자는 GUID만 허용하고 로그 디렉터리를 벗어나지 못한다.
- 파일 생성/시작 확인 후 조작 안내. 종료 행의 `duration-complete`를 확인해야 완료 표시.
  조기 종료·파일 미생성·시간 초과는 각각 실패로 알리고 반복 실행을 요구하지 않는다.
- 완료 파일을 Finder에서 선택한다. 앱/PC를 자동 종료하지 않는다. 외부 업로드 없음.
- 기록 시작30초/완료120초의 유한 대기이며 앱은 강제 정지하지 않는다.

### 3. 남은 지연 구분용 진단

정상 실행에는 계측을 켜지 않는다. 진단 실행의90초 동안만 프레임 간격, 네이티브
조회, 컨트롤러/CPU 렌더, 업로드, 창 이동, 전체 handler 및 handler 사이 시간의
구간별 최대값을 집계한다. 프레임별 배열을 보유하지 않으며 반초마다 기존 bounded
큐에 요약만 기록한다. 수집 종료 후 단계 시간 측정도 중단한다.

이 값은 AppKit 표시/GPU 완료/모니터 출력 프레임 시간이 아니다. 조회 구간은
scene-cache/pointer 읽기를 포함하며 worker의 실제 조회 소요시간 전부를 재는 것도
아니다. 첫 표본의 집계 프레임 수가0일 수 있고 각 표본은 이전 완료 handler들의
집계다. 이번 변경은 지연 원인을 확인할 수단이지 지연 해결 주장으로 쓰지 않는다.

## 다음과 미완

수정 후보는 준비됐다. 실제 맥에서는 상단 드래그와 놓기 직후의 위치 일치만 우선
확인해야 한다. 펫을 화면 밖에 잃는지, 클릭 위치가 일치하는지도 해당 수정의 수락 조건이다.
별도 지연이 남으면 새로운 단계별 집계를 사용하되 이번 턴에는 재조작/재수집을 요구하지
않았다. 외장 클램쉘·모든 환경·장시간 누수 해결은 통과로 바꾸지 않았다.
JOENESS 분석은 별도 담당이 진행하며, 그 결과를 앱 수정의 통과 조건으로 혼합하지 않는다.
